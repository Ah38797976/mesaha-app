# مساحتنا — أحمد ❤️ سلم اخواله

تطبيق خاص لشخصين، مبني على React + Vite ويعمل بالكامل على Supabase
(Auth, Postgres, Realtime, Storage, RLS). هذا مشروع حقيقي قابل للنشر — وليس Demo.

## ملاحظة مهمة قبل البدء

هذا الكود لا يعمل كمعاينة حيّة داخل هذه المحادثة، لأنه يحتاج مشروع Supabase
حقيقي (رابط + مفتاح API) ومتصفح فعلي يشغّل Vite — وهذه أشياء خارج بيئة
المعاينة هنا. اتبع الخطوات التالية على جهازك لتشغيله فعليًا.

## 1) أنشئ مشروع Supabase

1. اذهب إلى https://supabase.com وأنشئ مشروعًا جديدًا (مجاني).
2. من **SQL Editor** الصق محتوى الملف `supabase/schema.sql` كاملاً وشغّله.
   هذا ينشئ كل الجداول، RLS، الفهارس، الـ Storage buckets، وربطها بـ Realtime.
3. من **Authentication → Providers** تأكد أن "Email" مفعّل (مفعّل افتراضيًا).
   يفضّل أيضًا تعطيل "Confirm email" أثناء التجربة الأولى (Authentication → Settings)
   حتى يدخل كل طرف مباشرة بدون تفعيل بريد.
4. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`

## 2) اضبط متغيرات البيئة

```
cp .env.example .env
```

واملأ:
```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=xxxxxxxx
```

**لا تضع هذه المفاتيح داخل GitHub بشكل مباشر** — استخدم `.env` محليًا،
وفي Vercel أضفها كـ Environment Variables (الخطوة 4).

## 3) شغّله محليًا

```
npm install
npm run dev
```

افتح الرابط الذي يظهر (عادة http://localhost:5173).

### سيناريو الاستخدام الأول
1. أحمد يفتح التطبيق من قطر → "أنشئ حساب" → يدخل اسمه ودولته وبريده وكلمة سره.
2. بعد الدخول يظهر تبويب "أنشئ مساحة" → يحدد تاريخ بداية العلاقة → يحصل على **كود دعوة**.
3. أحمد يرسل الكود لسلم اخواله (واتساب/أي وسيلة).
4. سلم اخواله تفتح نفس رابط التطبيق من موريتانيا → "أنشئ حساب" باسمها ودولتها →
   تختار تبويب "انضم بكود" → تدخل الكود → تدخل المساحة.
5. من هذه اللحظة يظهر عند الاثنين: **أحمد ❤️ سلم اخواله**، والدردشة والصور
   والصوت والرسائل السرية وكل شيء يتزامن فورًا عبر Supabase Realtime.

## 4) انشر على Vercel

1. ادفع المشروع إلى مستودع GitHub خاص بك.
2. من https://vercel.com → New Project → اختر المستودع.
3. في **Environment Variables** أضف نفس القيم من `.env`:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. Build command: `npm run build` — Output directory: `dist` (Vercel يكتشفها تلقائيًا لمشروع Vite).
5. Deploy. بعدها كل من أحمد وسلم اخواله يستخدمان نفس رابط Vercel من بلديهما.

## ما الذي تغيّر عن النسخة المحلية

| كان (Local demo) | صار (Online) |
|---|---|
| `window.storage` (تخزين محلي وهمي) | جداول Supabase حقيقية + RLS |
| رسائل ثابتة داخل الكود | جدول `messages` + Realtime |
| `setTimeout` يحاكي رد الطرف الآخر في مجلسنَ | جدول `majlis_answers` — كل طرف يجيب فعليًا |
| `addImage` / `addVoice` وهميين | رفع حقيقي إلى Supabase Storage (صور + `MediaRecorder` للصوت) |
| ذكريات/مناسبات/قصص/عبارات في `useState` محلي | جداول مستقلة مشتركة بين الطرفين مع Realtime |
| PIN `1234` كحماية وحيدة | Supabase Auth (بريد/كلمة سر) + RLS تمنع أي طرف ثالث |
| توقيت الجهاز | Postgres `timestamptz` (UTC) يُعرض محليًا عند كل طرف |

## الأمان

- كل جدول محمي بـ Row Level Security: يمكن لأي مستخدم قراءة/كتابة بيانات
  `couple_id` الخاص به فقط (انظر `is_couple_member()` في `schema.sql`).
- الـ Storage buckets خاصة (`public: false`) وتُقرأ عبر روابط موقّعة (signed URLs)
  تنتهي صلاحيتها، وسياسات RLS على `storage.objects` تمنع أي شخص خارج
  المساحة من الوصول للملفات.
- محاولة انضمام ثالث لنفس المساحة تُرفض تلقائيًا (Trigger `enforce_two_members`).

## حدود معروفة (لتختبرها بنفسك قبل الاعتماد الكامل)

- لم يتم اختبار هذا الكود فعليًا على متصفحين حقيقيين لأن بيئة هذه المحادثة
  لا تصل إلى الإنترنت الخارجي ولا تملك مشروع Supabase فعلي. راجع الكود
  وشغّله محليًا، وأخبرني بأي خطأ تواجهه لأصلحه معك.
- إعادة الاتصال بعد انقطاع الإنترنت تعتمد على إعادة الاشتراك التلقائي لـ
  Supabase Realtime؛ إذا لاحظت تأخرًا بعد انقطاع طويل، حدّث الصفحة.
- `MediaRecorder` للتسجيل الصوتي يحتاج HTTPS (يعمل تلقائيًا على Vercel)
  وإذنًا من المتصفح للوصول للميكروفون.
